# 平台表单与字段口径（Application Forms）

国内渠道主要吃「在线简历 + 字段表单」，不是邮件附件。本文件统一个字段填法与
**三处口径一致**规则（平台字段 / 打招呼语 / 简历）。

## 一、BOSS 直聘

| 字段/场景 | 规则 |
|---|---|
| 在线简历 | 与 01 一致；公司名用全称（与离职证明一致）；教育经历学制如实（统招/非全） |
| 个人优势 | 06 的 4 句模板，100-200 字；不堆技术名词 |
| 期望薪资 | 填 01 期望区间 `[X]-[Y]K`；**先在档案设好再让系统展示给 HR**（改一次平台会记录波动，别频繁调） |
| 打招呼 | 默认招呼语设置成 06 的 3 行模板（平台置顶语可存一份）；对心仪岗位逐个手改第三行钩子 |
| 期望城市 | 与 JD 城市对应岗位实时改（多城市投递时用「分身期望」思路，改完投完记得切回主力） |
| 认证/互动 | 回复率是权重——24h 内回复 HR 消息；不接电话时段开勿扰说明 |

## 二、猎聘 / 智联 / 前程无忧 51job / 拉勾

| 平台 | 差异与注意 |
|---|---|
| 猎聘 | 猎头触达为主；隐私设置先关「公开简历」再决定谁可见；薪资口径用「月薪×月数」的准确输入 |
| 智联 | B 端国企/制造业多；期望岗位词用更宽泛叫法（如「后端开发」而非细名） |
| 51job | 字段长，学历下拉有「统招」，如实选；简历附件 PDF ≤2 页 |
| 拉勾 | 技术岗精简版本；期望薪资只有档位，选档位覆盖期望下限的那档 |

## 三、公司官网 / 邮件投递

1. 官网表单：字段照抄 01，**不要**让 agent 自动提交（人工最后一步）；
2. 邮件投递：主题 `应聘<岗位>-<姓名>-<渠道要求格式>`；正文 5 行内（对位+钩子+附件说明）；
   附件命名 `姓名-岗位-简历.pdf`（不是 `main_公司_岗位.docx`——内部命名不要漏出去）；
3. 渠道要 PDF 时：`verify_resume.py --pdf` 通过后用导出的 PDF；没有 PDF 引擎的平台投 DOCX。

## 四、内推（脉脉/牛客/同事）

- 提供材料 标准：简历 PDF + 一句话对位（06 内推话术）+ 期望岗位代码（官网内推码）；
- 牛客内推帖只建链接；对帖子内容（回忆/评价）标 unverified。

## 五、字符与格式限制速查

| 处所 | 限制 |
|---|---|
| BOSS 个人优势 | 据平台实测 100-200 字稳妥（limit 变化以平台 UI 计数为准） |
| 招呼语首条 | ≤3 行；钩子 1 个数字 |
| 简历附件名 | `姓名-岗位-简历.pdf`（ASCII 兼容时也允许 `CV-<Name>.pdf`，外企场景） |
| 智联/51job 在线简历 | 模块字数各自 ≤2000（超了就裁 bullets 而不是砍模块） |

## 六、一致性检查（/apply Step 6 checklist 的依据）

三处（平台字段/招呼语/简历）必须同口径的项目：

1. 期望薪资区间与月数；
2. 城市/到岗时间；
3. 最近一段职级与公司名写法；
4. 关键技能声明级别（「熟练/熟悉」不许在不同处所漂移）。

不一致即 must-fix：以平台字段为主键（HR 看到的第一层）。
