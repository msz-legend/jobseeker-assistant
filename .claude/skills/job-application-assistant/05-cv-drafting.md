# 简历起草（CV Drafting，DOCX 管线）

把 01 档案 + 04 评估 + JD 三方输入，变成一份 `cv/main_<公司>_<岗位>.json` 内容 spec，
再由 `tools/build_cv.py` 渲染成 DOCX。**本文件管内容选择与裁剪，渲染由工具负责。**

## 一、激活模板

先读 `templates/cv/<active>/TEMPLATE.md`（默认 `base`）：页数上限、字体、已知坑都从 manifest 来。
`/add-template` 注册过自定义模板时以 managed block 为准。

## 二、spec 生成规则

Schema 见 `templates/cv/base/spec.example.json`。逐节规则：

1. **identity**：照抄 01 基本信息；contact 一行 `手机 | 邮箱 | 城市`；GitHub/作品集进 lines（投外企/大厂主工程线才留，普通岗删）；
2. **objective（求职意向）**：role 用 JD 的岗位名（贴合但不虚构职级），city 取 JD 工作城市，availability 来自 01；
   多个候选城市时只写与该岗位匹配的那一个（别让 HR 猜）；
3. **sections 顺序（默认）**：专业技能 → 工作经历 → 项目经历 → 教育经历 → 证书奖项（可选，应届/有强项才保留）；
4. **专业技能 bullets**：`[主语言/组件]：边界一句话`；从 04 里命中的 JD 核心栈挑 3-6 条，**顺序按 JD 命中度**不按你喜好；
5. **工作经历卡片**：header `公司 · 职位`（JD 定向时可在职位后加与岗位对位的副标：`Go 后端工程师（交易方向）`），meta `时段 | 城市`；
6. **bullets 选择**（每段经历 2-4 条）：
   - 从 01 对应段落取，**动词+方法+量化**（03 规则）；
   - 与 JD 关键词相关的排前；时间倒序；最近一段最丰满，越早越瘦；
7. **meta.keywords**：从 JD 提炼 ≤8 个硬技能关键词（逗号分隔），verify_resume 用它算覆盖率，不渲染。

## 三、页数预算与裁剪

`meta.pages_target` 来自 manifest（≤5 年经验 1 页；以上可 2 页）。超出时按序砍：

1. 砍与岗位最不相关的整段经历（年份 >7 且非晋升线）；
2. 砍「证书与奖项」整节（除非该 JD 关心）；
3. 技能行 6→4 条（保命中的）；
4. bullets 每条删从句保留主句，2 行→1 行；
5. project 节整节砍掉（经历卡已覆盖时优先砍项目）。

重建 → verify → 仍超页 → 重复。**不通过缩字号/调边距作弊**（那是模板的职责）。

## 四、定向改写边界（什么能改什么不能）

- ✅ 能做：重排、选条目、改写措辞贴合 JD 术语（03/六 对位）、objective 定制；
- ✅ 能做：把 JD 的岗位词映射成你的等价表述（02 的对位表）；
- ❌ 不能做：新增经历、给数字注水、把「了解」写成「熟练」；
- ❌ 不能做：照抄 JD 句式（招聘方 grep 自己 JD 反查）。

## 五、渲染与校验（/apply Step 5 的完整闭环）

```bash
python tools/build_cv.py cv/main_<公司>_<岗位>.json -o cv/main_<公司>_<岗位>.docx --style templates/cv/<active>/style.json
python tools/verify_resume.py cv/main_<公司>_<岗位>.docx --spec cv/main_<公司>_<岗位>.json --pages <N> --keywords "<meta.keywords>"
```

- FAIL 逐条修后重跑（占位符残留 / 缺板块 / 关键词覆盖 / 页数）；
- 渠道要 PDF 时加 `--pdf`（本机走 Word/WPS COM；都没有则文本层 PASS + WARN）；
- 最后**人工打开目检**：字体回退、对齐、孤行、空白页；WPS 和 Word 都能正常打开才算过。

## 六、一页视觉注记（base 模板固化的版式）

- 姓名 18pt 微软雅黑居中；联系方式 9pt 灰；板块标题 12pt 加粗+底线分隔；
- 经历卡右对齐时间（tab stop）；正文 10.5pt 宋体，行距 1.15；
- 禁止：照片（渠道硬要求除外）、多栏、表格嵌套、彩色字体、页眉页脚、QR 码。

## 七、应届/转行特例

- 应届（实习经历>工作经历）：实习卡放「工作经历」首位，bullets 强调可交付物与数据；
- 转行：sources evidence 不足时，专业技能节前面加「相关项目」夹带两条可证明的迁移证据，
  并在 04 的领域维评分里如实反映（不为了过 Gate 注水）。

## 八、渠道分级门规则（2026-10-22 定稿）

定向简历不是默认动作，按渠道分级：

| 渠道 | 版本 | 理由 |
|---|---|---|
| 猎头 / 内推 / HR 直联 | **定向版**（spec 重排，当日内完成） | 关键词初筛是转述给用人方前的第一道门票 |
| BOSS / 猎聘 海投批处理 | 通用版（JAVA / GO 各一份） | 冷投批次量大、时效优先，通用版零周转 |

- 定向版纪律（与 §四 一致）：重排 / 选条 / 映射等价表述，**零新增事实**；每份 spec 存
  documents/cv/specs/〔公司〕_〔岗位〕.json，meta.rewrite_note 记录裁剪与映射来源；
- 每次生成必跑 §五 的 verify 闭环（docx + pdf + verify PASS 才算成品）；
- 首批生效：以定向版交付的首批岗位（服务端架构 / 后端负责人），2026-10-22。
